# Архитектура и проверки

Milestis состоит из Next.js-приложения и отдельного пакета Firebase Functions. Зависимости, линтеры и сборки у пакетов независимы. Приложение также импортирует чистые доменные типы и конфигурацию из `functions/src/`.

## Карта кода

| Путь | Содержимое |
| --- | --- |
| `src/app/[locale]/` | Страницы, авторизация, кабинет и редактор |
| `src/app/api/` | Серверные маршруты, включая ИИ и checkout |
| `src/app/sites/[slug]/` | Публичные проекты |
| `src/proxy.ts` | Домены публикаций, локали, rewrite и предварительные редиректы |
| `src/editor/lib/modes/` | Реестр режимов, сохранение и восстановление через контракт режима |
| `src/editor/modes/` | `portfolio`, `photobook`, `event`, `menu` |
| `src/editor/image/` | [Контракты и обработка изображений](../../src/editor/image/README.md) |

| `src/config/`, `src/lib/firebase/` | Настройки, клиентский SDK, App Check и Admin SDK |

## Проекты и публикация

`projects/{id}` хранит владельца, режим, статус и сведения о публикации. `projects/{id}/data/content` содержит рабочие `theme` и `content`. Zustand хранит состояние редактора; `useAutoSave` и `save-project.ts` сохраняют его через контракт режима. `published_projects/{id}` — отдельный публичный снимок. Автосохранение не обновляет опубликованный сайт.

В выборе новых проектов доступны портфолио, фотокнига и меню. Режим мероприятий зарегистрирован и поддерживает существующие проекты, но скрыт в `src/lib/projects/creation-options.ts`.

| Режим | Адрес относительно домена публикаций | Доступ |
| --- | --- | --- |
| Портфолио | Поддомен `{slug}` | Публичный |
| Меню | Поддомен `{slug}` и пути страниц | Публичный при оплаченном доступе |
| Фотокнига | Путь `/{slug}?share=TOKEN` | По ссылке с токеном |
| Мероприятие | Путь `/{slug}?share=TOKEN` | По ссылке с токеном; гостевая загрузка через Anonymous Auth |

Slug резервируется сервером. Токен приватной публикации проверяется по хешу. Снятие с публикации закрывает доступ, сохраняя резерв адреса.

Портфолио, фотокнига и мероприятие используют `analyzeProject → publishProject`. Анализ выдаёт расчёт стоимости и проверяет фотографии через SafeSearch. Публикация переносит используемые медиа в публичное хранилище и архивирует проект; после публикации очищаются приватные медиа. Для изменения опубликованного снимка проект снимают с публикации, затем используют `analyzeRepublish → republishProject`. Доплата — `max(0, новая стоимость − ранее оплаченная)`. Правила стоимости находятся в `functions/src/projects/publish/config.ts`.

Меню использует отдельные `menuBilling → publishMenu`, сохраняет черновик и оригиналы и обновляет снимок без снятия с публикации. [Данные, QR, гостевая сессия и оплата меню](../menu.md).

`proxy.ts` управляет навигацией, а права проверяются обработчиками и Firebase Rules. Admin SDK использует права сервисного аккаунта. Окончательное удаление доступно серверной операцией и планировщиком для записей `deleted` с наступившим `purgeAt`.

## Кредиты и подписки

Polar создаёт checkout в Next.js и доставляет подписанные webhook в `webhookPolar`. Тариф определяется metadata продукта `tier`. Серверные лимиты — `functions/src/users/upsertSubscription.ts`, клиентские условия — `src/lib/billing/`. Меню списывает кредиты по своему пакету; это отдельный механизм от подписки аккаунта.

`functions/src/transactions/engine.ts` атомарно обновляет баланс пользователя, партии `creditLots`, историю и запись защиты от повтора. Доступные кредиты исключают просроченные партии. Порядок списания: подписочные → бонусные → купленные; внутри источника — ближайшее истечение.

Повтор с тем же ключом и параметрами возвращает результат; другие параметры дают `idempotency_conflict`. Расхождение баланса и партий даёт `balance_inconsistent` без записи. Ручная правка `users.balance` нарушает этот учёт. Для компенсаций есть [административный API](../admin-credits.md).

ИИ не списывает кредиты: чат ограничен отдельным счётчиком, улучшение фото не имеет пользовательской квоты. [Доступ и лимиты ИИ](../ai-editor.md#доступ-и-лимиты).

## Автоматические проверки

| Команда | Назначение |
| --- | --- |
| `npm.cmd run check:config` | Development-настройки и согласованность проекта и Functions |
| `npm.cmd run configure -- --check --production` | Актуальность генерируемых production-файлов без записи |
| `npm.cmd run lint` | ESLint приложения |
| `npm.cmd --prefix functions run lint` | ESLint Functions |
| `npm.cmd run test` | Все тесты с фиксированным окружением |
| `npm.cmd run typecheck` | Генерация типов Next.js и TypeScript |
| `npm.cmd --prefix functions run build` | Компиляция Functions и проверка собранных модулей публикации |
| `npm.cmd run build` | Production-сборка Next.js с проверкой типов |
| `npm.cmd run check` | Production-конфигурация, оба линтера, тесты и обе сборки |
| `npm.cmd run verify:clean` | Чистые установки и проверки в отдельной временной папке |

Перед `check` выполните `npm.cmd run configure -- --production`. Тесты используют имитации внешних зависимостей. Общий загрузчик TypeScript-модулей — `tests/support/source-loader.mjs`; у каждого экземпляра свои моки и кеш.

`verify:clean` копирует существующие tracked и неигнорируемые новые файлы в системную временную папку, устанавливает оба пакета, генерирует конфигурацию, выполняет `check`, запускает production-сервер и проверяет HTTP-ответы. Папка сохраняется для разбора результата. Секреты, реальные env-файлы и результаты сборки не копируются; выбранные несекретные production-настройки записываются отдельно. Нужен доступ к npm registry и Google Fonts.

Автоматические проверки не подтверждают реальные платежи, ответы ИИ, Firebase Rules в эмуляторе или браузерные сценарии.

## Проверка на развёрнутом окружении

Используйте отдельного пользователя и Polar sandbox.

1. Проверьте вход по Google, паролю и email-ссылке, выход и повторный вход.
2. Создайте доступные режимы проектов, измените текст и фото, перезагрузите редактор и проверьте сохранение.
3. Опубликуйте портфолио, фотокнигу и меню с дополнительной страницей. Откройте ссылки без авторизации; для фотокниги проверьте доступ с верным, неверным и отсутствующим share token.
4. В меню проверьте QR, обновление по тому же адресу, рекомендации, сохранение корзины между страницами и игру.
5. Для существующего мероприятия загрузите фото гостем и дождитесь обработки: signed PUT, CORS и SafeSearch.
6. Проверьте чат, отмену, защиту ручной правки и сохранение улучшенного фото. Кредиты за эти операции не списываются.
7. Купите тестовые кредиты и подписку. Проверьте тариф, баланс и повторную доставку webhook без повторного начисления.
8. Проверьте оплату и смену пакета меню, отключение автопродления, запуск задач и закрытие доступа после истечения срока.
9. Проверьте отмену подписки, тестовый возврат, снятие публикации, удаление проекта, экспорт данных и назначение/отзыв `creditsAdmin`.

## Разбор ошибок

| Симптом | Что проверить |
| --- | --- |
| `Missing configuration` | Env-режим, имена переменных и перезапуск сервера |
| `Configuration needs regeneration` | `configure` в том же режиме, что проверка |
| Запрещён emulator origin | Пустой `NEXT_PUBLIC_FIREBASE_FUNCTIONS_ORIGIN` в production |
| Firebase `permission-denied` | Проект, UID, rules, claims, права сервисного аккаунта и App Check |
| `unauthorized-domain` | Authorized domains и `authDomain` |
| Functions: 404 или CORS | Проект, регион, имя экспорта, деплой и origin |
| Не загружается гостевое фото | Anonymous Auth, CORS, `signBlob`, логи `uploadEventPhoto` и `processEventPhotos` |
| Оплаченная подписка не изменилась | Режим Polar, продукт, metadata `tier`, webhook и секрет |
| `BALANCE_INCONSISTENT` | Согласованность баланса с `creditLots`; пополнение само по себе её не исправляет |
| Ошибка ИИ | Runtime-секрет, модель, доступ и квоты провайдера |
| Публикация недоступна | DNS, TLS, wildcard, передаваемый host, share token или оплата меню |
| Сборка не загружает шрифты | Доступ к Google Fonts, DNS и прокси |
