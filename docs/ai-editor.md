# ИИ в редакторе

## Подключение

Для локальной разработки добавьте в `.env.local`:

```dotenv
OPENAI_API_KEY=your-api-key
```

Перезапустите Next.js. Ключ используется только сервером. Нужны действующая сессия Firebase и доступ Firebase Admin к проектам и медиатеке.

Для Firebase App Hosting создайте секрет `openai-api-key`, предоставьте backend доступ к нему и выполните развёртывание. Привязка `OPENAI_API_KEY` уже добавлена в `apphosting.yaml`. Не добавляйте ключ в `NEXT_PUBLIC_*` или в репозиторий.

### Ошибка App Hosting «Misconfigured secret»

Запись в `apphosting.yaml` ссылается на Secret Manager, но сама секрет не создаёт. Значение из `.env.local` тоже не переносится автоматически. Для проекта `milestis` backend называется `milestis`, регион — `europe-west4`.

Проверить наличие секрета и его версий без вывода ключа:

```powershell
firebase.cmd apphosting:secrets:describe openai-api-key --project milestis
```

Если секрет отсутствует, создайте его и введите API-ключ в скрытом приглашении CLI:

```powershell
firebase.cmd apphosting:secrets:set openai-api-key --project milestis
```

Выберите использование в production и backend `milestis`. Привязка в YAML уже существует; повторно добавлять переменную не нужно. Если секрет создан отдельно или доступ ещё не выдан:

```powershell
firebase.cmd apphosting:secrets:grantaccess openai-api-key --backend milestis --location europe-west4 --project milestis
```

После настройки повторите развёртывание backend в Firebase App Hosting. Не передавайте значение ключа аргументом команды или сообщением в чат. [Документация Firebase](https://firebase.google.com/docs/app-hosting/configure#secret-parameters).

Модель: `gpt-6-sol`, Responses API, `reasoning.effort: low`, `store: false`. [Документация модели](https://developers.openai.com/api/docs/models/gpt-6-sol).

## Как работает

- Браузер отправляет название разрешённой операции, ID проекта и входные данные в `/api/ai`.
- Сервер проверяет сессию, владельца проекта, соответствие операции режиму, размер запроса и лимит использования.
- Инструкции и схемы ответов находятся в `src/lib/ai/server`. Клиент не задаёт модель, системные инструкции или схему.
- Изображения разрешаются по ID через записи медиатеки с проверкой владельца и проекта. Для чтения меню используется полноразмерное фото.
- Ответ GPT проверяется по схеме. Меню дополнительно проходит общую проверку связей блюд, категорий и страниц.
- Изменения применяются к черновику целиком. Ручное редактирование, смена проекта и отмена прерывают запрос и запрещают применение устаревшего результата.

Чат меню создаёт и редактирует категории, блюда, цены, страницы и шаблон. Последние восемь текстовых сообщений передаются как контекст текущего сеанса; история не хранится после перезагрузки. Неизвестные цены остаются `null`: такие блюда не попадают в опубликованное меню до заполнения цены.

В чате доступна отмена последнего изменения меню, пока после него не было других правок. Закрытие чата завершает текущий запрос; повторное открытие сохраняет сообщения текущего сеанса, но не кнопку отмены.

## Ограничения

Чат сейчас доступен владельцам проектов без подписки. Предохранитель расходов: 30 операций в минуту и 120 в сутки UTC на пользователя, до 24 000 выходных токенов на операцию. Портфолио и фотокнига используют несколько операций на одно сообщение. Отменённые и неудачные попытки тоже учитываются; повторного автоматического запроса к модели нет. Счётчик хранится в серверной коллекции `aiUsage`.

## Улучшение фото блюда

В окне редактирования блюда выберите фото из медиатеки, стиль и нажмите «Улучшить фото». Сравните результат с оригиналом, нажмите «Применить», затем сохраните блюдо. Оригинал остаётся в медиатеке. До применения результат хранится только в браузере. Смена стиля сбрасывает предпросмотр; новый запрос запускается только кнопкой «Улучшить фото».

Для тестирования функция доступна владельцам меню без подписки и без счётчика бесплатных обработок. Лимиты чата к ней не применяются. Обычный лимит места в медиатеке продолжает действовать при сохранении.

Серверный маршрут `/api/ai/enhance-photo` проверяет сессию, владельца меню и фотографии. Он использует тот же `OPENAI_API_KEY` и вызывает Images API: `gpt-image-2.5-flare`, `quality: medium`, `1024x1024`, один результат WebP с качеством сжатия 85. Исходник берётся из версии `middle`, если она доступна. Дополнительного запроса к текстовой модели и автоматических повторов генерации нет.

Доступны три стиля с серверными промптами в `src/lib/ai/server/enhance-photo.ts`:

- `eveningWood` — деревянная доска вместо тарелки или одноразовой упаковки, тёмный ореховый стол, вечерний ресторан и тёплые огни ламп.
- `daylightCeramic` — светлая керамическая посуда, известняковый стол и мягкий дневной свет.
- `darkSlate` — сланцевая доска вместо тарелки, тёмный каменный стол и мягкое направленное освещение.

Для супов, соусов и напитков сохраняется подходящий тип ёмкости. При съёмке сверху фоном служит только стол. Лёгкая ретушь разрешена, но состав, порция, форма, степень приготовления, расположение еды и ракурс должны сохраняться. Менять посуду разрешено согласно выбранному стилю. Промпты запрещают чрезмерный блеск, искусственную текстуру и приукрашивание еды. Это инструкция модели, а не гарантия точного сохранения деталей: перед применением пользователь видит оба изображения. Клиент передаёт только ID стиля; отсутствующий или неизвестный стиль отклоняется до генерации.

«Применить» загружает результат через существующую очередь загрузки и обработку изображений. Фото блюда меняется только после получения постоянного URL. При задержке сохранения повторное нажатие использует уже начатую загрузку без новой генерации. Новая Cloud Function не требуется.

## Проверка

```powershell
npx.cmd tsc --noEmit --incremental false
npx.cmd eslint src/lib/ai src/app/api/ai src/editor/components/editor/layout/Modals/AiChat src/editor/modes/menu/index.tsx src/editor/modes/menu/dish-dialog.tsx src/editor/modes/menu/photo-enhancement.tsx src/editor/image/editor/wait-for-image.ts
node --test tests/ai-editor.test.mjs tests/editor-reliability.test.mjs tests/menu-foundation.test.mjs
```

Для ручной проверки войдите в аккаунт, откройте меню и кнопку «ИИ»: создайте меню из списка с ценами, исправьте одну цену, задайте уточняющий вопрос, прикрепите фото бумажного меню, отмените последнее изменение. Во время генерации измените блюдо вручную: ответ не должен перезаписать правку. Проверка настоящих ответов требует настроенного ключа и доступа аккаунта к модели.
