# Администрирование кредитов

Администратор ищет пользователя по email или UID и начисляет компенсацию бонусными кредитами без срока действия. Это начисление новых кредитов; оно не отменяет исходное списание и не исправляет расхождения баланса.

## Доступ

Право `creditsAdmin: true` хранится в Firebase Auth Custom Claims. Function `adminCredits` при каждом запросе читает актуальный аккаунт администратора: устаревший ID token не обходит отзыв права. Отключённые аккаунты не могут начислять или получать компенсации. Клиентские claims управляют видимостью пункта меню.

Из корня проекта:

```powershell
node functions/scripts/set-credits-admin.cjs --project PROJECT_ID --email YOUR_EMAIL --grant --firebase-cli
```

Без `--apply` команда показывает проект, пользователя и действие. После проверки повторите её с `--apply`. Вместо email можно использовать `--uid`. Другие Custom Claims сохраняются.

Отзыв доступа:

```powershell
node functions/scripts/set-credits-admin.cjs --project PROJECT_ID --uid USER_UID --revoke --firebase-cli --apply
```

`--firebase-cli` использует учётную запись `npm.cmd exec -- firebase login`; для нестандартного расположения пакета есть `FIREBASE_CLI_PATH`. Без флага используются ADC: `gcloud auth application-default login` либо `GOOGLE_APPLICATION_CREDENTIALS`. Аккаунту нужны права управления Firebase Auth выбранного проекта.

После назначения откройте `/ru/account/admin-credits` и нажмите «Обновить права доступа» либо войдите заново. В настройках появится «Начисление кредитов».

## Начисление

1. Найдите пользователя по email или UID; проверьте получателя и доступные кредиты.
2. Укажите целое количество от 1 до 100 000 и причину от 3 до 500 символов.
3. Проверьте подтверждение и нажмите «Начислить кредиты».

Общий движок одной транзакцией обновляет баланс, партию и историю. Источник — `bonus`, тип — `admin_adjustment`, `meta.reason` — `support_compensation`, причина — `meta.note`, инициатор — `meta.adminUid`. Идентификатор запроса привязан к администратору; повтор с другими параметрами отклоняется.

Интерфейс сохраняет незавершённый запрос в `sessionStorage`. При потере ответа или перезагрузке вкладки повторяется тот же запрос. До выяснения результата не создавайте новое начисление: сверяйте историю или завершайте повтор. Намеренно созданные операции в разных вкладках независимы.

При расхождении баланса с `creditLots` начисление блокируется. Ручное изменение `users.balance` не заменяет транзакцию и не исправляется компенсацией.

## Код и проверки

Сервер — `functions/src/transactions/admin/`, назначение роли — `functions/scripts/set-credits-admin.cjs`. Для работы нужны развёрнутая `adminCredits` и приложение; записи выполняет Admin SDK.

`tests/admin-credits.test.mjs` проверяет права, отзыв, валидацию, атомарность и повторы; `tests/admin-credits-ui.test.mjs` — доступ и восстановление запроса. Оба входят в `npm.cmd run test`, реальные начисления не выполняют.
