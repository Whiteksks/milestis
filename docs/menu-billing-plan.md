# Оплата меню кредитами

Обновлено 27 сентября 2026 года. Реализовано в репозитории: тарифы, подтверждение оплаты при публикации, ежемесячное списание, управление автопродлением и проверка публичного доступа. Развёртывание не выполнялось.

## Тарифы

| Блюда с фотографиями | Кредитов в месяц |
| --- | ---: |
| 0–50 | 200 |
| 51–100 | 350 |
| 101–150 | 500 |
| 151–200 | 650 |

Пакеты определены в `functions/src/projects/menu/billing/model.ts`. Владелец может выбрать более вместительный пакет. Посещения и трафик на стоимость не влияют.

Сервер считает блюда с фотографиями в публичном содержимом меню. Одно блюдо на нескольких страницах учитывается один раз. Разные блюда с одинаковой картинкой занимают отдельные места. Скрытые блюда, скрытые категории, категории без страницы и изображения только в библиотеке не учитываются. Логотип и обложки страниц входят бесплатно. Существующий лимит каталога — 200 блюд всего — сохранён.

Общий `countUniquePhotos` используется для других режимов и считает URL изображений. Для меню добавлен `countMenuDishPhotos` в `functions/src/domain/menu/content.ts`, использующий ту же публичную проекцию, что и публикация.

## Оплата в интерфейсе

В окне публикации владелец сохраняет черновик и нажимает «Проверить стоимость». Сервер возвращает количество блюд с фото, выбранный пакет, сумму сейчас, доступные кредиты и дату следующего списания. Пакеты, в которые меню не помещается, недоступны.

Для ненулевого списания нужно подтвердить сумму и условия автопродления. Кнопка показывает стоимость. При недостатке кредитов доступна ссылка на пополнение; после пополнения нужно обновить расчёт. Баланс в этом окне исключает уже просроченные кредиты.

После публикации и в окне QR доступны состояние оплаты, текущий лимит, дата следующего списания, отключение/включение автопродления и переход к выбору пакета. В истории операций отдельно подписаны ежемесячная оплата меню и доплата за пакет. Переводы добавлены для ru/en/kz.

## Правила списания

- Первая публикация оплачивает календарный месяц. Начало и конец периода фиксируются при расчёте стоимости; расчёт действует 10 минут.
- Повторная публикация в пределах оплаченного пакета бесплатна.
- Повышение пакета списывает полную разницу цен сразу, независимо от оставшихся дней. Дата продления сохраняется.
- Понижение действует со следующего периода. Оно доступно, только если новое публичное содержимое помещается в выбранный пакет. Возврата за текущий период нет.
- Отмена автопродления сохраняет доступ до конца оплаченного периода. Включить его обратно без списания можно, пока период оплачен и меню опубликовано.
- Месяцы отсчитываются от исходной даты в UTC: 31 января → 28/29 февраля → 31 марта.
- Задача `renewMenuBillingCron` запускается раз в час. При нехватке кредитов повторяет попытки в течение трёх дней; в это время меню доступно. Затем доступ и автопродление останавливаются.
- Повторная активация после остановки оплачивает новый месяц без задолженности за пропущенное время.
- Для продления используется опубликованное содержимое. Изменения черновика влияют на оплату только после подтверждения публикации.

## Серверная архитектура

`menuBilling` — HTTPS POST с Firebase Bearer token. Действия:

- `status`: `{ projectId, action: "status" }` — состояние оплаты меню; не зависит от кредитного баланса.
- `review`: `{ projectId, action: "review", planId? }` — расчёт, без списания.
- `autoRenew`: `{ projectId, action: "autoRenew", autoRenew, revision }` — изменение автопродления с проверкой версии состояния.

`publishMenu` принимает `{ projectId, slug, locale, quoteId }`. Расчёт в `menuBillingQuotes` привязан к владельцу, проекту, содержимому черновика и версии оплаты. При изменении данных, истечении расчёта или пересечении границы платёжного периода требуется новый расчёт.

Сначала сервер проверяет расчёт и копирует медиа. Затем одной транзакцией списывает кредиты, публикует снимок, сохраняет `projects/{id}.menuBilling` и квитанцию результата. Ошибка копирования или изменившийся черновик не списывают кредиты. Повтор запроса с уже использованным расчётом возвращает квитанцию без повторного списания, пока эта публикация остаётся текущей. Расчёты и квитанции удаляются по TTL `deleteAt` через сутки; удаление Firestore асинхронное.

В `menuBilling` хранятся текущий и следующий пакеты, количество фото, версия состояния, платёжный период, статус, автопродление и идентификатор последней операции. Публичный resolver проверяет оплаченный период/льготные три дня при каждом запросе независимо от задержки планировщика. При отсутствии доступа гость видит нейтральную страницу недоступности.

## Учёт кредитов

Движок в `functions/src/transactions/engine.ts` проверяет соответствие баланса остаткам `creditLots`. Списание использует только непросроченные партии: подписочные → бонусные → купленные, внутри источника — ближайшее истечение. Баланс, партии, история и защита от повторной операции сохраняются атомарно; чтения предшествуют записям.

Повтор операции с теми же параметрами возвращает сохранённый результат. Изменение параметров при том же ключе даёт `idempotency_conflict`. Расхождения баланса дают `balance_inconsistent` без изменения данных. Исторические расхождения автоматически не исправляются.

Расчёт и публикация возвращают HTTP 409 с `BALANCE_INCONSISTENT`, если остатки партий не соответствуют балансу. Интерфейс объясняет, что нужна проверка начислений; обычное пополнение не исправляет расхождение. Просмотр состояния меню и отмена автопродления остаются доступны. Для тестовых начислений нужно использовать операции кредитного движка, которые записывают баланс, партии и историю вместе, вместо ручного изменения `users.balance`.

`expireCreditsCron` раз в час обрабатывает просроченные непустые партии страницами по 200 записей. Истечение использует актуальный остаток внутри транзакции и не увеличивает статистику потраченных кредитов. Просроченные партии перестают участвовать в оплате сразу, независимо от запуска задачи.

## Проверка и развёртывание

Локальные тесты проверяют реальную бизнес-логику на модели транзакций Firestore: атомарность, конкуренцию, повтор запросов, границы пакетов, подсчёт фото, смену тарифа, календарные месяцы, нехватку средств, отмену/возобновление и публичный доступ. Проверки не обращаются к рабочей базе.

Перед запуском нужны:

1. Индексы из `firestore.indexes.json`: продление по `menuBilling.autoRenew` и `menuBilling.nextAttemptAtMillis`, истечение по `creditLots.expiresAtMillis` и `remainingAmount`; TTL для `menuBillingQuotes.deleteAt`.
2. Cloud Functions: `menuBilling`, обновлённая `publishMenu`, `renewMenuBillingCron`, `expireCreditsCron`.
3. Обновлённый фронтенд. Адрес API задаётся `NEXT_PUBLIC_MENU_BILLING_URL` или строится из Firebase project ID для региона `europe-west4`.
4. Проверка оплаты и запуска задач в тестовом Firebase окружении.

Существующие меню без нового состояния оплаты после развёртывания потребуют активации через окно публикации. Миграция старых платёжных записей и рабочие данные не изменялись. Реальные Cloud Scheduler, индексы и браузерный сценарий требуют проверки в развёрнутом окружении.
