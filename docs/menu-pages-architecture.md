# Страницы меню: база архитектуры

Дата: 26 сентября 2026 года. Выполнены контракт данных и редактор страниц:
вкладки над canvas, создание, переименование, адреса, смена главной страницы,
удаление страниц и назначение категорий. Добавлены публичные маршруты `/drinks`,
навигация, QR страниц и публикация всего меню одним снимком.
Портфолио не изменено. Статус неопубликованных изменений не входит в этот шаг.

## Контракт

Оболочка документа остаётся `{ theme, content }`. В `content.sectionContent`:

```text
venue                           общие данные заведения и валюта
categories[]                    общий каталог категорий
dishes[]                        общий каталог блюд с categoryId
homePageId                      постоянный ID главной страницы
pages[]
  id                            постоянный ID страницы
  name                          название, независимое от адреса
  path                          канонический путь: / или /drinks
  content.categoryIds[]         ссылки на категории в порядке этой страницы
```

Тема, видимость секций, логотип и изображения блюд пока общие для проекта.
Изображения остаются в `content.imageContent`, привязка к блюдам — по ID.
Порядок массива `categories` больше не задаёт порядок показа: его задаёт
`page.content.categoryIds`. Порядок блюд внутри категории определяется массивом
`dishes`. Категория может использоваться на нескольких страницах без копирования.
Удаление пустой категории удаляет её ссылки со всех страниц. Непустую категорию
по-прежнему сначала нужно освободить от блюд.

## Инварианты

- У проекта ровно одна главная страница с путём `/` и ID из `homePageId`.
- ID и пути страниц уникальны внутри проекта. Название не изменяет путь.
- Первая версия поддерживает один сегмент пути: строчные латинские буквы,
  цифры и дефисы. Query, hash, вложенные пути и служебные адреса не принимаются.
- Все ссылки на категории существуют; повтор категории внутри страницы запрещён.
- Лимиты: 20 страниц, 30 категорий и 200 блюд на весь проект.
- Пустые названия и `priceMinor: null` допустимы в черновике.
- Повреждённые связи, дубли и превышение лимитов вызывают ошибку чтения.
  Восстановление больше не удаляет такие данные незаметно.
- Новый проект получает пустую главную страницу. Панель добавляет категории на
  выбранную страницу; canvas и предпросмотр отображают её состав.

## Управление страницами

- `page-commands.ts` содержит чистые команды создания, изменения, удаления страниц
  и назначения категорий. Проверки выполняются до изменения Zustand.
- `activeMenuPageId` находится в UI-store. При смене проекта выбор сбрасывается,
  при удалении выбранной страницы используется главная. Переключение страниц не
  изменяет содержимое и не запускает автосохранение.
- Создание страницы предлагает свободный путь `/page-N`. Название и путь задаются
  независимо. Редактор проверяет конфликты путей, служебные адреса и лимит страниц.
- Смена главной атомарно обменивает пути: выбранная получает `/`, прежняя главная
  получает бывший путь выбранной. Назначение главной и правки её полей сохраняются
  одной операцией.
- Главную страницу нельзя удалить, пока другая не назначена главной. Удаление
  любой другой страницы оставляет категории, блюда и изображения в каталоге.
- «Добавить из каталога» назначает существующую категорию. «Убрать со страницы»
  удаляет только ссылку. Создание и порядок категорий принимают явный `pageId`.
- Название, видимость и блюда категории общие для всех использующих её страниц;
  интерфейс объясняет это. Удаление категории из каталога по-прежнему возможно
  только после удаления или переноса её блюд.
- Вкладки поддерживают стрелки, Home/End и горизонтальную прокрутку. Настройки
  страниц и подписи переведены на ru/en/kz.

## Редактор меню: первый вариант интерфейса

- Окно создания и настройки страницы использует ту же оболочку, что публикация:
  диалог на компьютере и выдвижную панель на телефоне. Новая страница требует
  названия; адрес предлагается по названию (латиница, русский и казахский),
  проверяется на конфликт и остаётся ручным после правки владельца. Адрес уже
  созданной страницы при переименовании автоматически не меняется.
- Внутри выбранной страницы панель редактора показывает вкладки категорий.
  Выбор категории находится в UI-store и не сохраняет проект. `+` рядом с
  вкладками создаёт именованную категорию либо добавляет существующую из общего
  каталога. Панель показывает блюда одной категории, а canvas — страницу целиком.
- Новое блюдо создаётся в выбранной категории через форму: название и цена
  обязательны, описание и фото раскрываются отдельно. Отмена не создаёт пустую
  запись. «Сохранить и добавить ещё» открывает чистую форму в той же категории.
  Создание и правка содержимого с фото записываются одним изменением store.
  Перенос блюда доступен только между категориями текущей страницы; после
  переноса панель переключается на целевую категорию.

## Границы модулей

`functions/src/domain/pages.ts` содержит общий контракт страницы с параметром
содержимого, правила путей и поиск по пути. Подключён только к меню.

`functions/src/domain/menu/content.ts` содержит типы меню, лимиты, чтение данных,
выбор категорий страницы и построение публичного содержимого. Эти же исходники
импортируют редактор и Cloud Functions. В домене нет React, Zustand, Firebase
или Node API. Физическое расположение внутри `functions/src` позволяет включать
модуль в существующую сборку и Firebase-деплой без копирования исходников.

Редактор отвечает за мутации и интерфейс. Публикация — за права, транзакции,
адрес проекта и копирование изображений. Формат изображений остаётся частью
существующей медиасистемы.

## Публикация

Публичное содержимое включает только используемые страницами видимые категории
с заполненными видимыми блюдами. Неиспользуемые категории, блюда и их изображения
остаются в черновике. Снимок сохраняет ID главной страницы и состав страниц.

Все страницы публикуются одной транзакцией вместе с каталогом и изображениями.
Пустые страницы сохраняются и показывают нейтральное сообщение; для публикации
нужно хотя бы одно заполненное видимое блюдо среди всех страниц.

`/` выбирает главную страницу, `/{pagePath}` — страницу с точным путём из снимка.
Неизвестные и удалённые пути дают 404. Вложенный маршрут принимает только `menu`;
проверки опубликованности и статуса проекта выполняются общим серверным загрузчиком.
Загрузчик кешируется в пределах запроса, поэтому metadata и HTML используют один снимок.
Canonical и заголовок относятся к выбранной странице; изображение превью общее для меню.

Шаблон получает `pageId` явно. На публичном сайте навигация использует ссылки,
в canvas и предпросмотре — callback выбора без изменений содержимого.

Окно QR читает страницы из опубликованного документа с правами владельца.
После публикации получает их из ответа сервера. Адреса черновика в QR не попадают.
Переименование пути или смена главной вступают в силу после обновления публикации;
старые пути не перенаправляются. QR сохраняется, пока сохраняется адрес страницы.
Редактор объясняет это рядом с полем адреса.

## Исправления

- Клиент и сервер используют единое ограничение ID: 80 символов.
- Проверка кадрирования отклоняет прямоугольник, выходящий за границы изображения,
  с допуском на погрешность вычислений.
- Неподдерживаемый сохранённый формат не превращается в частично очищенное меню.

Миграции старого формата без страниц нет. Старые тестовые проекты меню потребуют
пересоздания либо отдельного явного преобразования. Никакие удалённые данные
в ходе этого изменения не изменялись.

Все 56 тестов прошли, как и TypeScript приложения, линтер затронутого кода,
production-сборка Next.js, компиляция Functions и проверка загрузки собранных

В headless Edge на временной локальной странице проверены создание, выбор мышью

проверены вкладки, длинное название и диалог без горизонтального переполнения.

После подключения публичных страниц добавлены проверки обновления адресов только
после успешной публикации, смены главной, удаления, изоляции режимов, 404,

адаптеры маршрутов Next.js с подменой загрузчика, без обращения к Firebase.
В Edge проверены навигация предпросмотра без записи в content-store, выбор страницы

Временная страница проверки удалена.

После обновления интерфейса прошли 66 тестов; TypeScript, линтер изменённых файлов,
production-сборка Next.js и сборка модулей Functions прошли. В Edge проверены

## Гостевой список выбора

Гость добавляет видимые блюда в список, меняет количество и показывает список
официанту. Логика количества и определения доступности общая для режима меню;
кнопки и панель списка находятся в шаблоне. Редакторский canvas остаётся
поверхностью редактирования, а предпросмотр даёт попробовать выбор в памяти.

В публичном меню браузер хранит только ID блюд и количество под ID проекта.
Поэтому выбор сохраняется между адресами страниц одного меню и после перезагрузки,
но не смешивается с другим заведением. Названия и цены всегда берутся из текущего
опубликованного снимка. Удалённое или скрытое блюдо остаётся в списке как
недоступное, без цены, пока гость не уберёт его. Список не создаёт заказ.

Первый персонаж пока нарисован средствами браузера: спокойное состояние,
короткая реакция на добавление и на удаление блюда. Событие содержит тип действия,
ID блюда и последовательный номер; будущую иллюстрацию можно заменить без
изменения логики выбора. При включённом уменьшении движения реакция не анимируется.
Плашка Milestis не показывается в опубликованном меню и его предпросмотре;
для остальных режимов она остаётся в общем публичном рендере.

## Гостевой шаблон

Один шаблон меню оформлен как спокойная ресторанная страница: компактная шапка,
горизонтальная лента страниц и закреплённая лента категорий. Страницы листаются
жестом на телефоне; стрелки появляются на широком экране только при переполнении.
Текущая категория подсвечивается при прокрутке. Блюда представлены читаемыми
строками с фото при наличии, описанием, ценой и крупной кнопкой выбора. Превью
шаблона в каталоге обновлено. Структура данных и публичные адреса не менялись.
